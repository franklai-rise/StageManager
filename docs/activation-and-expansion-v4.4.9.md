# v4.4.9 激活与展开修复记录

## 现场诊断

- VPN Manager 主窗口存在、响应正常，直接置前验证成功。
- Clash 主窗口存在且响应消息，但处于最小化状态；它由提升权限的 VPN Manager 启动，普通权限进程无法可靠地直接恢复或抢占前台。
- 历史日志也记录过 Clash、微信、Zotero、Explorer 等窗口被 Windows 拒绝前台激活，因此不能把一次 `SetForegroundWindow` 返回值当作最终结果。

诊断过程没有切换 VPN、代理或 Clash 配置，也没有结束相关进程。

## 修复

- 激活前解析 root-owner 与最后一个可用弹窗，避免主窗口被模态对话框挡住。
- 删除模拟 Alt 键的抢焦点方式；激活后分两次校验和重试，且用户已经切换到其他窗口时立即停止。
- 对仍处于托盘最小化状态的目标，按应用标题和进程名精确匹配通知区图标并调用；没有可靠匹配时不误点其他图标。
- 最终仍被 Windows 拒绝时，只闪烁目标任务栏按钮。
- 多窗口主卡触碰即展开，子卡按 35 ms 间隔、200 ms 动画依次向下流出；延迟中的卡片暂不接受点击。

## 验证

- 自动回归：67 项全部通过。
- 覆盖即时悬停展开、动画级联时序、动画前点击隔离、通知区匹配精度及原有窗口、Focus、桌面和设置行为。
- 本版本未更改 VPN/Clash 的权限级别；若目标以管理员权限运行，Windows 的权限边界仍可能拒绝普通权限程序直接控制，通知区回退用于处理其常见的托盘恢复路径。
